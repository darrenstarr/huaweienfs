# esunrpc public API reference

Step-by-step programmer's reference for the `esunrpc.ko` exported
API. Lives outside `vendor/esunrpc/` deliberately: the headers in
`vendor/esunrpc/include/esunrpc/` are mechanically regenerated by
`scripts/fork-sunrpc.sh` on every kernel-pin bump, and any
hand-written content in those files would be lost. This directory
holds the durable hand-written documentation.

The structure mirrors a classic library reference:

- `0-getting-started.md` — minimum-viable example: create a client,
  call NULL, tear down.
- `1-clients.md` — `esunrpc_rpc_create`, `esunrpc_rpc_clone_client`,
  `esunrpc_rpc_shutdown_client`, lifecycle, refcount semantics.
- `2-calls.md` — `esunrpc_rpc_call_sync`, `esunrpc_rpc_call_async`,
  `esunrpc_rpc_run_task`, return-code conventions, retry policy.
- `3-transports.md` — `xprt_create_transport`, multipath via the
  switch, transport-state observability.
- `4-auth.md` — AUTH_SYS, AUTH_NULL flavors, when to use each.
- `5-multipath.md` — the `rpc_xprt_switch` model, iter ops, how
  enfs.ko's round-robin sits on top.
- `appendix-symbol-index.md` — every exported `esunrpc_*` symbol,
  with one-line summary + pointer to the chapter that explains it.

## Conventions used by these docs

Every public-API entry has the same shape:

```
## esunrpc_<name>(args) — short purpose

**Signature:**

    return_type esunrpc_<name>(args);

**Purpose**

What it does, in one or two paragraphs. The "why this exists"
question is more important than the "what it does line-by-line"
question — that's what the source is for.

**Arguments**

- `arg1` — what it is, what is and isn't allowed
- `arg2` — what it is, what happens if it's NULL

**Returns**

What the return value means, including all the error cases.

**Locking and context**

Whether the caller must hold any lock. Whether it sleeps. Whether
it can be called from interrupt or atomic context.

**Threading**

Reentrancy. Whether multiple callers may concurrently use the same
struct.

**Lifetime**

Whether the function takes a reference. Whether the caller still
owns the input. Whether the return value is owned by the caller.

**Example**

    /* Idiomatic use, including error handling and cleanup. */

**See also**

Related entries by name.
```

This format is borrowed from the Linux kernel's "kernel-doc"
convention (the comments that `scripts/kernel-doc` knows how to
extract), with the addition of explicit Lifetime and Threading
sections because those are the most common things to get wrong
when writing against an RPC client.

Every chapter here has a corresponding man page under
`docs/man/esunrpc/`. The man pages are generated from these
markdown sources via pandoc — see `Makefile` rule `manpages-esunrpc`
and chapter 15 §15.10 of the internals book.
